# 产品范围与可行性

## 产品目标

应用把“可编辑的音乐数据”转成“可以听、可以看、可以导出”的演奏项目。用户只需导入一份文件，选择声音和视觉方案，即可生成类似参考视频的成片。Mac 为首发平台，曲谱、演奏计划和渲染核心保留后续 iOS 复用能力。

成功标准包含三个层面：曲谱表达正确，音符与声音同步，导出画面具有参考视频中的纸面透视、彩色光点、光轨和连续运镜。音频拟真程度另设质量标准，不能把“发出小提琴音色”视为“达到真人小提琴演奏”。

## 参考视频拆解

参考文件时长分别约 139.55 秒和 184.17 秒，均为手机屏幕录制。录屏的 1320 × 2868 分辨率、60 fps 和播放器控件属于载体信息，不代表原始成片规格。

| 观察项 | 第一段 Rush E | 第二段 Golliwogg’s Cakewalk | 应用对应能力 |
| --- | --- | --- | --- |
| 乐谱 | 数字排版，接近正面，轻微透视 | 印刷风格纸页，斜向透视 | 排版与纸面材质分离 |
| 光点 | 金色、青色为主，逐音符或和弦发亮 | 多色光点及局部纸面光晕 | 按声部或演奏轨道配色 |
| 轨迹 | 抽查片段以光点为主 | 连奏组有短弧线，同音延续有长线；分离伴奏光点移动时可不连线 | 先按 slur 或 tie 判断资格，再控制表现和密度 |
| 镜头 | 随乐谱进度向下跟随 | 平移、倾斜视角及构图变化 | 根据未来音符位置预先规划镜头 |
| 输出 | 横向乐谱成片嵌在竖屏播放器里 | 同左 | 导出实际成片，不包含录屏黑边与播放器 UI |

观察依据包括开头、中段、结尾抽帧，第一段 9.0 至 10.6 秒，以及第二段约 149、150.6、158 至 159、173.8 至 175.4 秒的连续帧。同屏连奏与分离伴奏的对照说明，光点移动、速度或音量本身不足以决定连线。原作者的内部实现仍不能由成片唯一恢复；本项目已采用曲谱显式 slur 与 tie 关系作为必要条件，详见[光点轨迹与自动运镜](04-visual-effects-and-camera.md)。

## 用户流程

1. 导入 `.musicxml`、`.mxl` 或本应用的 `.scorefilm`。
2. 查看解析报告：曲名、乐器与声部、预计时长，以及无法正确播放或排版的内容。
3. 为整首、声部或时间段选择乐器；选择主题、光点配色、轨迹模式和运镜预设。
4. 准备演奏，播放、暂停、拖动进度，并随时查看当前声部与段落。
5. 保存项目；选择画面比例、分辨率和帧率，导出带音频的视频。

Mac 界面采用文档窗口。中央是画面预览；左侧显示曲谱结构、声部和配器段落；右侧显示当前选项；底部提供传输控制和时间尺。首版支持段落范围编辑和参数调整，完整五线谱音符编辑器留在后续阶段。

## 首版范围

| 能力 | 首版约定 |
| --- | --- |
| 输入 | MusicXML 4.0 的已验证子集、常规单乐谱 MXL、自定义项目文件 |
| 曲谱 | 常用音高、休止、和弦、多声部、多谱表、拍号、调号、附点、连音组、延音线、连奏线、力度和速度 |
| 演奏结构 | 普通反复、第一与第二结尾；跳转类结构必须通过原型语料验证，否则明确阻止演奏导出 |
| 乐器 | 钢琴与小提琴至少各一套可分发音源；支持分声部及分段配器 |
| 播放 | 从头播放、暂停、停止、定位、静音和独奏；更改配器或速度后重新准备音频 |
| 效果 | 光点、局部光晕、仅连奏组与延音链内部的可选轨迹、两种纸面风格、自动运镜 |
| 视频 | 1080p，30 与 60 fps，SDR，H.264 与 AAC 的 MP4；支持取消和失败后重试 |
| 保存 | 原谱、项目参数和自有资源引用随项目保存；自动保存与正常另存为 |

4K、HEVC、HDR、外部 AU 插件、录音对齐、PDF 识谱、自动扒谱、真人手指或运弓动画，以及完整打谱器，均放在首版之后。未来如加入 MIDI 导入，需提供量化和谱表拆分，因为 MIDI 通常缺少原始的连奏、拼写和版面语义。

## 文件完整性与支持完整性

“能够保存整份曲谱”与“首版能够准确排版和演奏每一种记谱”是不同要求。

文件采用完整 MusicXML 源和可扩展的应用设置，避免把曲谱压缩成仅含音高、开始时间、时长的简化 JSON。导入时保留原始字节；未知节点不会在保存时被默默删除。MusicXML 之外的现代图形谱、任意自由记谱和特定出版社版式不能承诺通用互换。

每个导入特性分别标记为“已支持”“保留但不参与演奏”“需要用户补充”“阻止导出”。不认识的装饰音或跳转会影响音乐结果，应阻止对应演奏导出；不影响音乐时间的版面提示可以告警并允许继续。参见[格式与能力规则](03-scorefilm-file-format.md)。MusicXML 的记谱和声音信息本身也有区分，例如 `<tie>` 与 `<tied>` 的职责不同。[官方音符定义](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/note/)

## 可行性与质量风险

| 项目 | 判断 | 需要证明的部分 |
| --- | --- | --- |
| 曲谱导入与重新排版 | 可行，有成熟排版库 | 复杂和弦、跨谱表、连音组和音符坐标映射正确 |
| 钢琴与小提琴合成 | 可行，系统提供采样乐器及离线音频接口 | 音源质量、复音、力度及奏法解释 |
| 分段或分声部更换乐器 | 可行，自有路由层即可处理 | 边界上的延音、踏板、释放音和重复段落 |
| 光点及光轨 | 可行，几何与着色计算规模可控 | 音符着陆时间、线条密度、纸面光照和可读性 |
| 自动运镜 | 可行，按谱面和未来事件离线规划 | 多声部同时发声、换行换页、反复跳转与镜头舒适度 |
| 同步视频导出 | 可行，可逐帧渲染并编码 | 长片无累计漂移、编码背压、色彩和尾音 |
| 真人级弦乐表情 | 成本明显高于基础音色播放 | 连弓、换弓、揉弦和采样切换，不作为首版默认承诺 |

首个技术原型不需要 Blender 或 AE 作为运行依赖。它们可用于美术对照；应用内使用自己的时间线、渲染和编码管线。Polyfjord 的相近工程可作为效果参考，不能据此推断其工程或素材可以直接随本应用分发。[官方效果介绍](https://polyfjord.teachable.com/)
