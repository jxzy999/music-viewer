# Music Viewer：Mac 乐谱演奏与可视化应用方案

本项目拟制作一款 Mac 应用：导入结构化曲谱，选择乐器、声部配色、纸面风格、光点和光轨模式，自动合成演奏并生成运镜画面，最后导出带声音的视频。视觉目标来自 `files` 中的《Rush E》和《Golliwogg’s Cakewalk》两段录屏。

**结论：可以实现。建议首版采用 SwiftUI 与 AppKit、OpenSheetMusicDisplay、Metal、AVAudioEngine 和 AVAssetWriter。先验证乐谱坐标映射、乐器合成和音画同步，再完成产品界面。** 成片质感主要取决于乐谱排版、音源和视觉调校，不能仅由“支持导出”推断已经达到参考视频效果。

初稿日期为 2026 年 10 月 28 日，轨迹条件于 2026 年 10 月 29 日修订。现已建立可运行的 Mac 开发版本，完成双乐器预览与真实视频导出；当前功能、实测结果和剩余验收项见[开发与验证记录](09-development-status.md)。

## 核心决策

1. **保留完整曲谱源。** 以 MusicXML 4.0 保存常用西方记谱语义，应用自己的文件补充乐器路由、演奏解释、特效和镜头设置。MIDI 只作为后续导入来源，不能承担完整记谱保存。
2. **共用一份演奏计划。** 声音、光点、轨迹、镜头都引用相同的音符和展开后的播放时间；排版引擎不掌握播放时钟。
3. **首版预先合成音频。** 使用离线合成得到可缓存的 PCM，播放和视频导出复用它。点击播放前允许显示“准备演奏”；暂不承诺边改配器边实时无缝试听。
4. **排版只在内容变化时进行。** 排版输出纸面图像和音符锚点，Metal 负责每一帧的动态效果。视频从离屏渲染直接编码。
5. **两种预设都交付。** “清晰跟谱”对应第一段的近正面阅读效果；“电影纸面”对应第二段的斜视、局部光晕、曲线拖尾和缓慢运镜。
6. **轨迹由曲谱连接关系限定。** 只有有效连奏组 slur 或延音链 tie 内部允许连线。普通相邻音、分离伴奏和无连接关系的重复音只显示光点；任何预设、模式或覆盖均不能绕过这一条件。

## 第一阶段要证明的结果

用一份包含钢琴伴奏和旋律声部的结构化曲谱，完成“前半段钢琴、后半段小提琴”的配器，播放时同步显示彩色光点与按规则生成的轨迹，并导出一段 1920 × 1080、60 fps、带音轨的视频。该结果通过后，才进入完整 Mac 产品开发。

最低系统版本和性能基线在原型阶段根据实际设备与 SDK 决定。可先以 macOS 14 及以上、Apple Silicon 为设计假设；这不是对本机版本的检测结论，也不涉及现有项目的系统版本调整。
