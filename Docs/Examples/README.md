# 原创格式示例

[Duet.scorefilm](Duet.scorefilm) 是项目格式草案的 ZIP 示例，解包内容与 [Duet 目录](Duet/) 一致。它供实现导入器和编译器时使用，当前不是已经能播放的应用作品。

## 内容

- 原创四小节练习，4/4 拍，含两个 part 和三个谱表。
- P1 是旋律声部，第一与第二小节使用钢琴，第三与第四小节使用小提琴。
- P2 是双谱表钢琴伴奏，上谱表 voice 1、下谱表 voice 2。
- 前两小节 96 QPM，后两小节 84 QPM。全曲 16 个四分音符拍，记谱时长为 `8 × 60 / 96 + 8 × 60 / 84 = 75 / 7` 秒，约 10.714286 秒，不包含声音尾音。
- 旋律包含普通连奏、同音高重复、断奏、延音链和休止；伴奏含和弦与 backup，便于检查并发时间。
- 项目启用斜视纸面、仅按显式连奏与延音关系生成的自动轨迹，以及自动运镜，目标输出 1080p60。它只是导出设置，不代表本次已经生成视频。

## 关键预期

| 情况 | 预期 |
| --- | --- |
| P1 第一小节 C4、D4、首个 E4 | 属于同一 slur 组，C4 到 D4、D4 到 E4 可显示短弧线，各音独立起音 |
| P1 第一小节两个 E4 | 首个 E4 已结束 slur，后一个为断奏；两次起音且不在两者之间连线，不能因同音高自动合并或连接 |
| P1 第二小节两个 G4 用 tie 相连 | 只起音一次，持续三个四分音符拍；两个印刷符头按进度指示并形成持音连接，不按 220 ms 的短拖尾时长裁短 |
| P1 第一小节末尾 E4 到第二小节 G4 | 没有连接关系，只显示各自光点，不因相邻而补线 |
| P1 第三小节开始 | 新起音交给 violin 实例，P2 继续钢琴 |
| P1 第三小节 E4、F4、G4、A4、B4 | 处于同一 slur 组，可按顺序连线；更换为小提琴不改变连接资格 |
| P1 第三小节 B4 到第四小节 C5 | slur 已结束，不跨组补线；第四小节普通长音仅持续高亮 |
| P1 第二与第四小节末尾休止 | 不从前一个音符跨休止连接发光轨迹 |
| P2 和弦与低音 | 同时发声；全段没有 slur 或 tie，光点可以移动但不连线；不能把 chord 和 backup 当成串行事件 |
| `p1m2n2` 的视觉覆盖 | 关闭从此锚点出发的连接，不影响 tie 链前半段或声音 |

`piano-v1`、`violin-v1` 是未来应用资源库中的逻辑键。本示例没有附带任何采样音源；GM program 只用于说明映射。应用实现时必须提供对应资源或报告资源缺失。

需要接近第一段参考时，可将 `visual.preset` 改为 `clear-score`、`visual.effects.trailMode` 改为 `off`、`camera.preset` 改为 `flatFollow`。配器和声音保持不变；重新打包时应更新项目设置的哈希。

`auto` 和 `travel` 都必须先通过 slur 或 tie 资格检查，不能强制给 P2 伴奏或第一小节的重复 E4 补线。现有示例参数及包内文件无需改变，本次同步的是其显示规则与预期结果。

## 校验层次

JSON Schema 校验设置结构，MusicXML 官方 XSD 校验 XML 结构；另外检查包内 SHA-256、ID 引用、小节拍值、路由范围和音符关系。上述静态检查不能证明排版、乐器声音、运镜或导出效果正确。

Schema 的 `additionalProperties: false` 用于当前版本严格校验；应用读取更新版本时应先处理版本与能力协商，并保留未知内容，不能拿旧 Schema 直接覆盖保存新文件。
