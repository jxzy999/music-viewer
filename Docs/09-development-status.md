# 开发与验证记录

记录日期：2026-10-29。Mac 首版使用原生 SwiftUI、AppKit、SwiftPM、离线 OSMD、AVAudioEngine 和 Metal，已具备导入到成片的制作链路。本文区分实际运行、自动化检查与发布前的外部验证。

## 工程与使用

仓库使用 `main`，远程地址为 `git@github.com:jxzy999/music-viewer.git`。应用名称已改为 **Music Viewer**，`script/build_and_run.sh` 构建完整的 `dist/Music Viewer.app`；Codex Run 按钮使用同一入口。首次更名时安全退出旧构建，再沿用原应用包内容完成改名；退出未完成时停止构建，不强制覆盖。`.scorefilm` 容器、已有工程标识及恢复副本位置继续兼容。

| 模块 | 当前实现 |
| --- | --- |
| ScoreCore | 有理拍轴、MusicXML 语义、原生 ZIP/MXL/ScoreFilm、哈希与原子保存、未知 XML/JSON 内容保留 |
| 演奏计划 | 多声部与和弦、普通与嵌套反复、第一第二结尾、分段配器、延音合并、踏板、数值速度及线性 QPM 覆盖、延长记号倍率、确定性微调、静音独奏 |
| ScoreMedia | OSMD 2.2.1 本地排版、源 ID 到符头映射、钢琴与小提琴离线 PCM、总线混响、缓存播放、Metal 绝对时间画面与 H.264/AAC 视频 |
| 原生界面 | 多窗口、系统文件打开、导入、段落配器、声部乐器与配色、静音独奏、纸面与运镜选项、播放暂停定位、保存另存、恢复副本、取消与错误处理 |

原谱字节不变，排版专用 ID 通过颜色标识桥接到 OSMD 源音符对象，渲染前恢复黑色；和弦使用 VexFlow 的明确符头索引，系统身份来自 GraphicalMeasure.ParentMusicSystem。不按 SVG 文档顺序猜音符。

音频实例区分 part、voice、staff、instrument 和同音重叠 lane。延音后续符头只有视觉事件，无第二次起音；钢琴双谱表共用延音踏板。总线使用中等房间混响，默认 12%，可以关闭。原谱未指定可用 GM 音源时要求明确选择，不自动替换成钢琴。

轨迹仅来自有效 slur 组或 tie 链；普通相邻音不连线，全局 off 优先。同位小回环仍受 slur 资格约束。短连奏历史与延音持音区间分别计时。电影纸面采用透视、局部照明与羽化光轨；清晰跟谱采用正交投影。预览和导出复用相同 ScenePlan、渲染器及 PCM；只改颜色、镜头或画幅时继续播放。

## 长片与同步

5 分钟压力谱包含 8 个 part、32 个 voice、32000 个音符、63 页，全部符头映射，7000 条合格连接。此前完整编码并解码 18164 帧、302.733333 秒的 1080p60 视频，PTS 严格递增，单次导出约 70.22 秒，见 `Outputs/Stress60Rerun/`。

最终分组合成与分页缓存版本见 `Outputs/GroupedStress/`：在编码进度约 46% 时实际取消，未留下完成影片或临时影片；同一窗口重新导出成功，18169 帧、302.816667 秒，单次导出约 93.11 秒，完整解码及帧时间检查通过。尾音判定因分组合成与房间效果而与历史版本略有差异。随后另起导出并执行原生退出，进程结束且不留下部分成片，见 `quit-during-export.json`。运镜检查 11552 个正在演奏的符头，安全区域越界 0。

脉冲语料使用生产解析器、时间线、AVAudioUnitSampler、PCM、Metal 与 MP4 导出器。它固定为一个受控纸面锚点，隔离媒体时钟；真实曲谱的排版映射由主样例、附加 MXL 及压力谱另行证明。

30 fps 的 306.25 秒语料逐项检查 140 个事件，解码音频偏移最大 1 个采样，视觉最大 29.167 毫秒，相对最大 29.188 毫秒，小于一帧加一个采样；首尾差 4.167 毫秒来自帧量化，不呈累积音频漂移，见 `Outputs/Sync30/sync-validation.json`。当前音频图的 60 fps 检查同样覆盖 140 个事件，最大音频偏移 1 个采样、视觉偏移 12.5 毫秒、相对偏移 12.521 毫秒，满足一帧加一个采样的门槛，见 `Outputs/Sync60Final/sync-validation.json`。

## 性能记录的范围

主样例 `Verified60` 的 2161 帧离屏绘制检查，热身后 p95 为 0.83 毫秒，首次帧约 26.62 毫秒；30 fps 的相同检查 p95 约 0.78 毫秒。竖屏 p95 约 0.98 毫秒。测量包含 CPU 提交与同步等待 GPU 完成，排除像素回读、哈希及 PNG 编码，不能当成实际屏幕刷新率。

检查结束时主进程历史驻留峰值约 533 MiB（`Verified60` 电影纸面）、526 MiB（清晰跟谱）。它不包括 WebKit 辅助进程，也不是完整任务结束后的全部进程峰值。还需在发布设备上记录真实预览的长时间掉帧、全进程内存及蓝牙播放延迟。

长片运镜曾同时露出 4 页，超过旧纹理缓存的 3 页容量，造成仍在视野内的页面反复解码。现保护完整可见集合，仅淘汰不可见的旧页。同一 32 声部压力谱、2161 帧离屏检查，热身后 p95 从约 133.30 毫秒降到 6.07 毫秒，首帧约 70.40 毫秒、共加载 15 次页面纹理，见 `Outputs/AcceptanceStressFinal/` 与 `Outputs/GroupedStress/rendering-performance.json`。后者主进程历史驻留峰值约 1102 MiB；两次均为本机单次开发构建记录，不是显示刷新率或全进程内存结论。

## 关键修正

- 首次压力谱缺少合法 direction-type，排版器跳过首小节；语料已修正，全部 32000 个符头映射。
- 曾按视频时间人为限制音频供数，引发编码背压等待；现按两路输入各自就绪状态供数，有限在途帧并带 30 秒无进展超时。
- 文件打开曾进入临时界面状态；现只注册实际窗口持有的工程，启动完成后再分发系统请求，同一窗口不保留旧状态对象。
- 从主线程任务调用退出，再返回 terminateLater，会使异步清理等待同一执行器。原生栈采样已确认；现先返回取消，异步回收完成后再次发起最终退出，不进入这层嵌套等待。
- 32 个 sampler 置于单个离线图时曾在系统音频库崩溃。现每组最多 8 个实例，依原采样轴合成后统一混音及峰值衰减；9 实例回归检查覆盖第二组较晚进入、静音间隔和峰值上限。实际 32 声部、5 分钟谱已完成分组合成，音频准备约 63.56 秒，总准备约 78.44 秒；这是一项稳定性规避措施，不声称已修复系统库内部缺陷。

## 支持边界与发布前验证

当前是本机可运行的开发版本，未配置签名发布、公证或商店流程。实际运行只覆盖上述 Apple Silicon Mac。Intel、其他 macOS 版本、真实音频设备热插拔、蓝牙时延与系统休眠恢复仍需对应硬件验证；测试响应方法不能替代这些证据。

应用更名为 Music Viewer 后，重新构建及启动检查通过；原生欢迎窗口、应用菜单、设置窗口及版本标题显示新名称。33 项回归检查再次通过，示例包完整性及本地文档链接校验通过。示例曲谱仅更新标题和创作者说明，既有媒体验收记录对应更名前的曲谱元数据；没有改动音高、时值、配器或连接关系。参考录屏保留在本地，源码、原创示例和运行资源纳入远程仓库。

首版采用已验证的 MusicXML 数值时值、音高、力度、速度与基础奏法。跳转类结构、装饰音、半踏板、微分音、八度线与复杂声音切换等尚未提供完整演奏解释，会阻止不完整的演奏；高级揉弦、运弓和真人级弦乐不属于首版承诺。完整原谱仍随工程保留。第三方资源与商业分发复核见[资源登记](10-third-party-resources.md)。

## 文件兼容

静音、独奏、混响均是向后兼容的可选参数；源谱和未来 JSON 扩展保留。用户清除已知可选字段时，保存不会从旧 JSON 中把它补回来；兼容读取的容器 minor 版本不自动降级。延长记号在公共时间轴扩展，线性 QPM 解析积分，反复入口恢复源谱位置的速度状态。
